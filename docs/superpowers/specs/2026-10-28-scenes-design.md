# 场景化助手与记录结构 设计稿

日期：2026-10-28 · 状态：待主人过目

## 1. 要解决的问题

1. **助手只有一种面孔**。不管丢进来的是一部电影、一篇论文还是一次踩坑，它都用同一个提示词，产出同一种「标题 / 摘要 / 要点 / 标签」。问的问题也千篇一律（"这是什么？"）。
2. **记录结构太扁**。所有条目都是同一组字段，所以：
   - 记的时候：电影该记的「星级、和谁看、台词」没有位置，踩坑该记的「现象、原因、怎么修」被塞进要点。
   - 翻的时候：想看「今年看过的电影海报墙」「还没解决的坑」「某个城市吃过的店」都做不到，只能在一条时间流里翻。
3. **旅程已经是独立模块**（`trip.html`），但随手丢进来的旅行照片和它不相通。

## 2. 核心想法：场景（Scene）

一个**场景**说清楚三件事：

| | 问题 | 例子（影视） |
|---|---|---|
| 记什么 | 这类东西值得留下哪些字段 | 片名、年份、导演、看的日期、和谁、星级、一句话短评、台词 |
| 怎么问 | 助手缺什么时问什么、语气如何 | "打几星？""和谁看的？"——最多两个，能从原文推断的不问 |
| 怎么翻 | 日后用什么视图找回来 | 海报墙；按 想看 / 在看 / 看完 筛；按年份、星级排 |

场景写成**一个文件**，像 skill 一样：Claude 以后加新场景、改字段，只改这个文件，不动代码。

```
scenes/
  _persona.md          # 助手的性格与说话方式（所有场景共用）
  film.md              # 影视
  game.md              # 游戏
  book.md              # 阅读
  art.md               # 展览 / 演出
  music.md             # 音乐（歌、专辑、现场）
  paper.md             # 论文
  tool.md              # 开源项目 / 工具
  motion.md            # 前端动效
  concept.md           # 概念 / 教程
  bug.md               # 踩坑
  meeting.md           # 会议
  place.md             # 探店 / 地点
  diary.md             # 日记 / 心情 / 小事（兜底的生活场景）
  note.md              # 兜底：认不出来时用它
```

### 2.1 场景文件长什么样

```markdown
---
id: film
name: 影视
group: taste            # taste 品味 / knowledge 知识 / life 生活
color: "#f2b544"
detect: 电影、剧集、纪录片、动画；豆瓣/IMDb/B站番剧链接；"看了""二刷""追剧"
fields:
  - { key: work,    label: 片名,     type: text,   required: true }
  - { key: year,    label: 年份,     type: number }
  - { key: creator, label: 导演/主创, type: text }
  - { key: status,  label: 状态,     type: enum,   options: [想看, 在看, 看完, 弃了], default: 看完 }
  - { key: date,    label: 看的日期,  type: date,   default: 今天 }
  - { key: with,    label: 和谁,     type: text }
  - { key: rating,  label: 星级,     type: stars }
  - { key: review,  label: 一句话,   type: text,   from: 用户原话优先 }
  - { key: quotes,  label: 台词/片段, type: list }
  - { key: progress,label: 进度,     type: text,   when: status=在看 }   # 第 9/12 集
ask:                    # 缺这些且推断不出来时才问，最多两个
  - rating
  - with
enrich: 联网补 年份、导演、海报（只补事实，不替用户写感受）
card: poster            # 首页卡片用海报样式
views:
  - { name: 海报墙, layout: poster-wall, sort: date desc }
  - { name: 想看,   filter: status=想看 }
  - { name: 年度,   group: year(date) }
---

## 怎么整理
- 用户的感受原样保留进「一句话」，不要润色成影评腔。
- 二刷 / 重看：找到已有条目，追加一次观看记录，而不是新建。
- ……
```

### 2.2 内置场景一览（第一版）

| 组 | 场景 | 关键字段 | 助手会问（最多两个） | 翻找视图 |
|---|---|---|---|---|
| 品味 | 影视 | 片名、年份、导演、状态、日期、和谁、星级、一句话、台词 | 打几星、和谁 | 海报墙、想看清单、年度 |
| 品味 | 游戏 | 名字、平台、状态、时长、星级、一句话、截图 | 玩了多久、通关没 | 封面墙、在玩、通关记录 |
| 品味 | 阅读 | 书名、作者、状态、进度、划线（带页码）、读后感 | 读到哪了 | 书架、划线集、年度书单 |
| 品味 | 展演 | 名字、场馆、日期、照片、印象 | — | 时间线、照片墙 |
| 品味 | 音乐 | 曲目/专辑、艺人、状态（在听 / 听过）、日期、在哪听到 / 当时的心情、星级、一句话、链接 | 喜欢到几星 | 唱片墙、在循环、年度 |
| 知识 | 论文 | 解决什么、怎么做、怎么评测、结论、链接 | 为什么存它（和什么有关） | 卡片网（带关联）、按主题 |
| 知识 | 项目/工具 | 用来干嘛、怎么装、适合场景、注意 | — | 工具箱（按用途） |
| 知识 | 前端动效 | 预览、实现（代码）、要点、参考 | 在哪看到的 | 动效画廊 |
| 知识 | 概念/教程 | 通俗讲、例子、容易混、相关 | — | 卡片网 |
| 知识 | 踩坑 | 现象、原因、怎么修、下次注意、已解决 | 解决了吗 | 未解决 / 已解决、按技术栈 |
| 知识 | 会议 | 参会、结论、待办、下次 | — | 按项目、待办汇总 |
| 生活 | 探店/地点 | 在哪、点了什么、人均、评分、照片 | 好吃吗 | 地图、按城市 |
| 生活 | 日记 | 一段话、心情、天气、照片 | 不问 | 日历、那年今日 |
| — | 兜底 | 标题、摘要、要点 | 这是什么 | 时间流 |

这些字段来自交接文档里已经画好的模板（论文、项目、动效、概念、会议、踩坑、探店、旅行），加上品味五类（影视、游戏、阅读、展演、音乐）。

**私密**：任何场景都不默认私密，只有主人在投递时勾选「私密」才私密（不发给助手、不进 GitHub 备份）。会议也一样。

## 3. 记录结构（数据）

### 3.1 一条条目 = 公共骨架 + 场景字段

```yaml
---
id: 20261028-213000-ab12cd34
scene: film                 # 新增
title: 花样年华
oneLine: 王家卫，雨夜那段太美了   # 卡片上的一句话（替代原来的长摘要做卡片文案）
date: 2026-10-27            # 这件事发生的日期（看片日、踩坑日、到店日），不同于入库时间
tags: [王家卫, 重看]
links: [https://movie.douban.com/…]
private: false
relations:                  # 已设计过的带类型链接
  - { to: 20250…, type: 改编自 }
fields:                     # 场景字段，按场景文件校验
  work: 花样年华
  year: 2000
  creator: 王家卫
  status: 看完
  with: 小林
  rating: 5
  review: 雨夜那段太美了
  quotes: [“如果多一张船票，你会不会跟我走？”]
cover: img-0.jpg            # 封面：用户的图优先，其次联网补的海报
---
（正文：整理后的说明，可选；原始内容、图片文字照旧放在后面的分段里）
```

- 仍是 Markdown + frontmatter，仍在 git 里，主人仍能用任何编辑器改。
- **旧条目不用迁移**：没有 `scene` 的视为 `note`，照旧显示。可以以后让助手批量「重新识别场景」，每条都要主人确认。

### 3.2 一个「作品」可以有多次记录

二刷电影、反复玩的游戏、分几次读完的书：条目是**作品**，每次接触是它下面的一条 **记录**（日期 + 一句话 + 照片）。首页信息流按记录出现，海报墙按作品出现。

### 3.3 和旅程打通

旅行期间（今天落在某趟旅程的日期内）丢进来的东西：
- 地点 / 吃的 → 场景照常识别（探店），同时写进旅程当天的日志或食记；
- 照片 → 进当天的照片；
- 条目上记 `trip: <旅程 id>, day: 2027-01-24`，旅程页和首页都能看到。

## 4. 助手：一个性格，多种场合

### 4.1 性格（`_persona.md`）

助手的名字叫 **小小蜗**。

主人希望助手像大家对 DeepSeek 的普遍印象那样：**专业，但有人情味**。落到具体行为上：

- **先给判断，再给理由**。像一个懂行的朋友，而不是客服。
- **说人话**。中文自然，不堆形容词，不写"影评腔""公文腔"；短问题短回答。
- **诚实**。不知道就说不知道；联网查到的事实附来源；不编年份、价格、班次。
- **记得你**。会用你以前的记录说话（"你上次给王家卫的《2046》打了 3 星"），但不卖弄。
- **尊重原话**。你的感受原样保留，只补事实和结构，不替你抒情。
- **有分寸的温度**。看到深夜写的日记不说教；看到踩坑解决了可以说一句"这个坑挺阴的"；不说"希望对你有帮助"。

**调研依据**（2026-10-28，用 free-search 检索）：
- 用户口中 DeepSeek 的「人情味」主要来自三点：中文自然、懂梗，长攻略后结尾一两句温暖的话，以及敢给判断。同一篇报道里的例句也显示了它的毛病：容易写成「你灵魂深处早已存在的回声」这类辞藻堆砌。[SBS 中文，2025-01-31](https://www.sbs.com.au/language/chinese/zh-hans/podcast-episode/whats-unique-about-this-chinese-ai-chatbot-deepseek/6bdjy8wk4)
- 两次反向争议说明分寸比温度更难：一次版本更新把语气改得「严谨客观」，用户嫌像冷冰冰的客服；深度思考里给用户起昵称被扒出来，用户又觉得被暗中评判。评论的结论是「懂人的前提是尊重人」，要透明、有分寸。[雷科技，2026-08-10](https://www.leikeji.com/article/78596)

因此在上面几条之外，再加两条硬规则：
- **温度只放在结尾一句，正文保持干货**；不写比喻排比、不写「灵魂」「回声」式的抒情。
- **不给主人贴标签、不做性格评判**；引用主人过去的记录时直说出处（"你 3 月记过……"），不暗中推断。

### 4.2 场合（同一个助手在不同地方的工作方式）

| 场合 | 在哪 | 它做什么 | 交互形态 |
|---|---|---|---|
| 收件整理 | 首页投递 → 草稿 | ① 认场景 ② 按场景填字段、联网补事实 ③ 只问最多两个关键问题 | 草稿卡片：字段表单 + 问题做成**可点的快捷回答**（★★★★☆ / 和谁：小林 / 自己） |
| 补一句 | 草稿页 | 主人回一句话，助手只改相关字段 | 对话条，改动高亮 |
| 找东西 | 搜索框 | 模糊回忆 → 找到条目，并说**为什么匹配** | "找到 3 条：最像的是……因为你当时写了 '自我进化'" |
| 回顾 | 那年今日 / 年度 | 把一段时间的记录串成几句话 | 只读，可一键生成年度报告 |
| 旅程规划 | 旅程页 | 已有，改行程 | 已接好的规划助手，换上同一份性格 |

技术上：场合 = 场景文件 + 场合提示词片段 + 允许的工具。整理时先用便宜的一步**只认场景**（输出 `scene` 和置信度），再用该场景的完整提示词生成草稿。认不准（置信度低）时草稿顶部给两个候选场景，主人点一下就换。

## 4.5 知识组按卡片盒（Zettelkasten）来做

主人要的不是"收藏夹"，而是原子化 + 链接的卡片盒。卡片盒的几条核心规则，和它们在小蜗里的对应：

| 卡片盒的做法 | 意思 | 在小蜗里 |
|---|---|---|
| **三种笔记分开** | 闪念笔记（随手记，临时）→ 文献笔记（读一个来源时记下的，用自己的话）→ 永久笔记（一个观点，脱离来源也能读懂） | 收件箱 = 闪念；论文/工具/动效等「来源」条目 = 文献笔记；新增 **卡片**（`card`）= 永久笔记 |
| **原子化** | 一张卡只讲一个观点，标题就是这个观点的一句话（"RRF 用排名而不是分数做融合，所以不用归一化"），不是主题词（"RRF"） | 助手从一篇文献笔记里**提议** 1–3 张卡片，每张标题是一句完整的话；主人勾选要留哪几张 |
| **用自己的话** | 卡片不是摘抄，摘抄留在文献笔记 | 卡片正文默认留空给主人写，助手只给一句草稿并标「草稿」；不愿写也可以直接用草稿 |
| **链接比分类重要** | 新卡片必须连到已有卡片，并写明**为什么**连 | 助手为每张新卡片找 2–3 张最相关的旧卡片，给出带类型的链接 + 一句理由（对比 / 前身 / 用到 / 支持 / 反驳 / 同主题）；主人确认 |
| **入口卡（结构笔记）** | 一个主题的目录卡，按顺序串起相关卡片 | 当某个标签下卡片超过 7 张时，助手提议建一张入口卡（MOC），主人可改顺序 |
| **固定编号** | 卡片 id 永不变，链接永不失效 | 沿用现有 id；改标题不改 id |
| **从链接里长出想法** | 翻卡片时顺着链接走，而不是靠搜索 | 卡片页底部显示「链到这里的」反向链接；知识组的默认视图是**卡片网**（局部关系图 + 列表） |

具体流程（以一篇论文为例）：

1. 丢进链接 → 助手按 `paper` 场景整理成文献笔记（解决什么 / 怎么做 / 怎么评测 / 结论）。
2. 草稿页下半部分：「可以拆出的卡片」——助手提议 2 张，每张一句话标题 + 一句草稿 + 建议链接到的旧卡片和理由。
3. 主人勾选 → 文献笔记和卡片一起入库，卡片自动链回来源。
4. 以后模糊地找"那个讲评测要用历史轨迹回放的"，搜索先命中卡片（一句话标题最好搜），再顺着链接到论文。

### 常见的坑，和小蜗的对策

| 坑 | 说明 | 对策 |
|---|---|---|
| **收藏家谬误** | 收进来就觉得「已经知道了」，链接和截图越堆越多却没有消化。[zettelkasten.de, The Collector's Fallacy](https://zettelkasten.de/posts/collectors-fallacy/) | 知识组的文献笔记如果 14 天没拆出卡片、也没写一句自己的话，首页「待消化」里提一下（每次最多 3 条，可一键「不需要」）；不催、不打分 |
| **拆得太碎** | 一句摘抄一张卡，卡片多但每张都读不懂 | 卡片必须是一句完整的观点，脱离来源也能读懂；助手提议时自检，做不到就不提 |
| **链接没有理由** | 到处双链，日后看不出为什么连 | 每条链接必须带类型 + 一句理由，没理由的不建 |
| **只有链接没有入口** | 卡片网很大，但不知道从哪开始看 | 主题卡（入口卡）+ 首页「最近长出来的卡片」 |
| **让工具替你思考** | 助手把卡片写完，主人只点确认，等于没学 | 卡片正文默认留空给主人；助手只给一句初稿并标「草稿」 |

不做的事：不强求每条都拆卡片（工具、动效、踩坑大多不需要）；不让助手自动建链接——都是提议，主人确认。

这条进入分期第 1 期：`card` 场景、文献笔记里的「可以拆出的卡片」、反向链接。卡片网视图放到第 5 期。

## 5. 翻找：每种东西有自己的看法

- **首页**保持现在的样子，加上真正的分类条（全部 / 游戏 / 影视 / 阅读 / 音乐 / 艺术 / 知识 / 生活），数字是真的。
- 点分类进入该组；组内按场景文件里的 `views` 切换视图：海报墙、书架、未解决的坑、地图、卡片网……
- 「正在进行」= 所有 `status` 是 在玩 / 在看 / 在读 的作品，加进行中的旅程。
- **搜索**：先做关键词 + 字段过滤，再做按意思搜（交给助手，返回为什么匹配）。

## 6. 分期

1. **场景骨架 + 卡片盒**：场景文件格式与加载、认场景一步、条目 `scene/fields/date/oneLine`、草稿页按字段渲染、快捷回答。先上 影视、阅读、踩坑、论文、卡片、兜底 六个；论文草稿可拆出卡片，卡片带理由的链接和反向链接（见 4.5）。
2. **补齐场景**：其余 9 个场景文件；首页分类条与「正在进行」；海报墙 / 书架 / 未解决 三个视图。
3. **作品与记录**：多次观看/游玩/阅读；二刷合并。
4. **旅程打通**：旅行期间的投递写进旅程当天。
5. **找东西**：搜索框、按意思搜、为什么匹配；回顾与年度报告。

每期单独可用、单独上线。
